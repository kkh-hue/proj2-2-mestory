# Spec — 리포트 메일 발송

- 담당: 박민영 · 상태: 작성 완료, 구현 대기
- 코드(예정): `backend/main.py`, `backend/email_sender.py`(신규), `backend/db.py`(조회 재사용),
  `frontend/app/reports/[id]/page.tsx`, `frontend/lib/api.ts`
- ⚠️ `backend/main.py`는 홍민하 님, `frontend/`는 강경희 님 영역 → PR 설명에 밝힌다

## Why

- **페르소나**: 설비 담당자. 분석 결과를 정비팀·관리자에게 넘겨야 한다.
- **상황**: 리포트를 다 읽고 나면 그 내용을 다른 사람에게 전달해야 한다.
- **문제**:
  1. **리포트를 화면 밖으로 내보낼 방법이 없다.** 공유하려면 화면을 캡처해서 메신저로 보낸다.
  2. 캡처는 원본 링크가 없어, 받은 사람이 상세 내용을 다시 볼 수 없다.
- **측정 지표**: 아래 AC 7개 통과 여부. 발송 성공률(수동 확인).

## Goal

- **해결 목표**: 저장된 리포트를 화면의 버튼 하나로 지정한 주소에 메일로 보낸다.
- **성공 기준**
  1. AC 7개 모두 통과.
  2. 허용 목록에 없는 주소로는 **단 한 건도 나가지 않는다.**
  3. 기존 API 계약 변경 0건(엔드포인트를 새로 추가만 한다).
- **Out of Scope**
  - 자동 발송·스케줄링·조건부 알림 — 사람이 버튼을 눌러야만 나간다.
  - 수신자 DB, 발송 이력 저장.
  - 서버에서 PDF를 만들어 첨부하는 것 — 브라우저 인쇄로 처리한다는 팀 결정이 이미 있다.
  - **SMTP** — Railway Hobby 플랜이 25·465·587 포트를 막아 쓸 수 없다.
  - 첨부파일, 예약 발송, 수신 확인(열람 추적).

## What

**Happy Path**

1. 사용자가 리포트 상세 화면에서 주소를 입력하고 "메일 보내기"를 누른다.
2. 프론트가 `POST /reports/{report_id}/email` 에 `{"to": "주소"}` 하나만 보낸다.
3. 서버가 **`report_id`로 DB에서 리포트를 직접 꺼낸다.**
4. 서버가 수신 주소를 **허용 목록(`.env`)과 대조**한다.
5. 서버가 메일 본문(HTML 표 + 텍스트 대체본 + 상세 페이지 링크)을 만든다.
6. Resend HTTPS API로 발송하고 200을 돌려준다.

> **3번이 중요하다.** 화면이 보낸 리포트 내용을 그대로 메일에 넣지 않는다.
> 그러면 누구나 요청 본문을 조작해 **아무 내용이나 담은 메일을 우리 도메인 이름으로** 보낼 수 있다.
> 서버는 `report_id`만 받고 내용은 스스로 조회한다.

**Edge Cases**

| # | 상황 | 처리 |
|---|---|---|
| EC-01 | 허용 목록에 없는 주소 | **403**. 발송기를 호출하지 않는다 |
| EC-02 | 없는 `report_id` | **404**. 발송기를 호출하지 않는다 |
| EC-03 | `to`가 메일 형식이 아님 | **422**(Pydantic 검증). 발송기를 호출하지 않는다 |
| EC-04 | 허용 목록 환경변수가 비어 있거나 없음 | **모든 주소를 403.** 기본값이 "열림"이 되면 안 된다 |
| EC-05 | Resend가 4xx·5xx를 돌려줌 | **502**. 서버는 죽지 않고 계속 응답한다 |
| EC-06 | `RESEND_API_KEY`가 없음 | 설정 오류로 **502**. 시작 시점이 아니라 호출 시점에 판단한다 |
| EC-07 | DB 연결 실패 | 기존 방식대로 **503** |
| EC-08 | 허용 목록의 대소문자·공백 차이 | 양쪽을 `strip()` + 소문자로 맞춰 비교한다 |

## How

```
POST /reports/{report_id}/email

요청 바디:
  { "to": "someone@example.com" }        ← 이것 하나뿐

응답 성공 (200):
  { "ok": true, "to": "someone@example.com" }

응답 실패:
  403  허용 목록에 없는 주소
  404  리포트 없음
  422  to가 메일 형식이 아님
  502  Resend 실패 또는 설정 누락
  503  DB 연결 실패
```

**새 환경변수 4개**

| 이름 | 예시 | 설명 |
|---|---|---|
| `RESEND_API_KEY` | `re_xxx` | Resend API 키. **비밀값이라 `.env`에만 둔다** |
| `REPORT_EMAIL_FROM` | `MESTORY <onboarding@resend.dev>` | 보내는 사람 |
| `REPORT_EMAIL_ALLOWLIST` | `a@x.com,b@y.com` | 쉼표 구분. **비어 있으면 아무도 못 받는다** |
| `FRONTEND_BASE_URL` | `https://mestory-app.up.railway.app` | 메일에 넣을 링크의 앞부분 |

**메일 본문**

- HTML 표: 설비·라인·기간·원인 건수·심각도별 요약
- 텍스트 대체본: HTML을 못 읽는 메일 앱을 위해 같은 내용을 글로
- 링크: `{FRONTEND_BASE_URL}/reports/{report_id}`

**제약**

- 발송 수단은 **Resend HTTPS API**. SMTP는 포트가 막혀 못 쓴다.
- 발송기(`backend/email_sender.py`)는 **HTTP 호출만** 담당하고 권한 판단은 하지 않는다.
  시험에서 이 함수 하나만 가짜로 바꾸면 "몇 번 불렸는지"를 셀 수 있어야 한다.
- 시험은 **실제 메일을 보내지 않는다.** 발송기를 모의 처리한다.
- Resend API의 정확한 요청 형식(엔드포인트·필드명)은 **구현 단계에서 공식 문서로 확인한다.**
  이 Spec은 "Resend HTTPS API를 쓴다"까지만 정한다.

## AC (Given-When-Then)

**AC-01 · 허용된 주소로 보내면 발송된다**
- GIVEN: 허용 목록에 `ok@example.com`이 있고, 그 `report_id`가 DB에 있다
- WHEN: `POST /reports/{id}/email` 에 `{"to": "ok@example.com"}`을 보낸다
- THEN: **200**을 돌려주고, 발송기가 **정확히 1번** 호출된다

**AC-02 · 허용되지 않은 주소는 막는다**
- GIVEN: 허용 목록에 `ok@example.com`만 있다
- WHEN: `{"to": "stranger@evil.com"}`으로 요청한다
- THEN: **403**을 돌려주고, 발송기가 **한 번도** 호출되지 않는다

**AC-03 · 없는 리포트는 404**
- GIVEN: DB에 없는 `report_id`
- WHEN: 허용된 주소로 요청한다
- THEN: **404**를 돌려주고, 발송기가 호출되지 않는다

**AC-04 · 메일 형식이 아니면 422**
- GIVEN: 허용 목록이 설정돼 있다
- WHEN: `{"to": "골뱅이없는문자열"}`로 요청한다
- THEN: **422**를 돌려주고, 발송기가 호출되지 않는다

**AC-05 · 허용 목록이 비면 아무도 못 받는다**
- GIVEN: `REPORT_EMAIL_ALLOWLIST`가 빈 문자열이거나 설정돼 있지 않다
- WHEN: 어떤 주소로든 요청한다
- THEN: **403**을 돌려주고, 발송기가 호출되지 않는다

**AC-06 · 메일 본문에 리포트 내용과 링크가 들어간다**
- GIVEN: 설비·기간·원인이 있는 리포트
- WHEN: 발송에 성공한다
- THEN: 발송기에 넘어간 본문에 **설비ID·기간·원인 건수**와
  `{FRONTEND_BASE_URL}/reports/{report_id}` 링크가 들어 있다

**AC-07 · 발송 실패해도 서버는 살아 있다**
- GIVEN: Resend가 오류를 돌려주도록 모의 처리한다
- WHEN: 허용된 주소로 요청한다
- THEN: **502**를 돌려주고, 예외가 밖으로 새지 않으며,
  이어지는 다른 요청(예: `GET /health`)이 정상 응답한다
