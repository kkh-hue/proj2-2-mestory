# MESTORY 기능 목록 (Feature List)

설비 다운타임 원인 분석 리포트 자동 생성 서비스에 들어갈 기능들을 우선순위별로 정리한 문서입니다. P0는 없으면 서비스가 성립하지 않는 필수 기능, P1은 여유가 있을 때 추가하는 기능입니다.

---

## P0 — 반드시 필요한 핵심 기능

### F-01. 정지 로그 조회 기능 (MCP 도구)
기간 / 라인 / 설비 조건을 입력하면 해당 조건에 맞는 정지 로그(downtime_log)를 가져오는 기능. 리포트 생성의 원재료가 되는 가장 기본적인 조회 기능.

### F-02. 에러코드 사전 조회 기능 (MCP 도구)
특정 에러코드를 조회해서 설명, 전형적 원인, 정상 정지시간 범위, 심각도를 가져오는 기능. 사전에 없는 코드를 조회하면 "없음"을 명확히 반환해야 함 (임의로 추정 원인을 만들지 않도록).

### F-03. 정비이력 조회 기능 (MCP 도구)
특정 설비의 최근 정비이력(예방/사후 정비, 조치 내용, 결과)을 가져오는 기능. 같은 문제가 반복될 때 근본원인을 추정하는 근거로 사용.

### F-04. 원인 분석 리포트 생성 기능
F-01~F-03에서 조회한 데이터를 근거로, LLM이 원인·심각도·근거·권장 조치를 담은 리포트를 정해진 형식(Pydantic 스키마)에 맞춰 생성하는 핵심 기능. LangChain 에이전트가 필요한 도구를 스스로 호출해서 데이터를 모으고 답을 만듦.

### F-05. 실패 안전 처리 기능
아래 상황에서는 원인을 지어내지 않고 "확인 필요"로 정직하게 응답하도록 강제하는 기능.
- 에러코드 사전에 없는 미등록 코드
- 정지시간이 음수이거나 비정상적인 값
- 에러코드가 비어있는 로그
이 기능이 없으면 LLM이 그럴듯한 원인을 지어내는(hallucination) 문제가 생김.

### F-07. 챗봇형 대화 UI
사용자가 "9월 라인A 리포트 보여줘" 같은 질문을 입력하면, 조건을 해석해서 리포트를 대화형으로 보여주는 화면. Streamlit 또는 React(Next.js)로 구현.

### F-08. Langfuse 트레이스 연동
모든 요청의 입력, 출력, 응답 시간, 토큰 사용량을 기록해서 나중에 어떤 질문에서 실패했는지, 얼마나 느렸는지를 확인할 수 있게 하는 기능. 서비스가 제대로 작동하는지 지속적으로 관찰(관측)하기 위해 필요.

### F-10. 출력 재시도/폴백 전략
리포트 생성이 정해진 형식(Pydantic 스키마)에 맞지 않게 나올 경우, ① 다시 시도 → ② 형식을 단순화해서 재시도 → ③ 그래도 실패하면 "자동 분석 실패, 원본 로그 확인 필요"라는 고정 안전 응답을 내보내는 3단계 안전장치.

## P1 — 여유 있을 때 추가하는 기능

### F-06. 복수 원인 우선순위 표시 기능
같은 시간대에 원인이 여러 개 겹쳐 발생했을 때, 잠정적인 우선순위와 함께 "이건 확정된 판단이 아니다"라는 불확실성 표시를 같이 보여주는 기능. (팀에 현장 진단 경험이 없어 확정 규칙은 아직 없음)

### F-09. 평가셋 자동 채점 스크립트
평가 질문 30건 이상에 대해 서비스가 낸 답과 미리 정한 정답을 자동으로 비교해서 정답률과 스키마 준수율을 계산해주는 스크립트. 개발 중간중간 품질을 빠르게 확인하는 용도.

### F-11. 심각도 등급별 알림 문구 커스터마이징
심각도가 "중대"인 경우 리포트 상단에 강조 표시나 "즉시 정비팀 확인 필요" 같은 문구를 자동으로 붙여주는 기능.

### F-12. 자재/정비팀 담당 구분 표시
원인이 설비 고장이 아니라 자재 문제(예: 원자재 공급 지연)인 경우, 권장 조치를 "정비팀"이 아니라 "자재팀 확인"으로 구분해서 안내하는 기능.

### F-13. 기간별/설비별 다운타임 요약 통계
리포트 본문 외에, 조회 기간 동안의 총 다운타임, 가장 많이 발생한 에러코드 Top 3 같은 요약 통계를 함께 보여주는 기능.

## 이번 프로젝트에서 하지 않는 기능 (범위 밖)

혼동을 줄이기 위해 명확히 제외하는 기능도 같이 적어둡니다.

- 실시간 설비 제어나 자동 조치 실행 (최종 판단·조치는 항상 사람이 함)
- 여러 라인을 동시에 스케줄링하는 기능
- RAG(문서를 청크로 쪼개 검색하는 방식) 기반 지식 응답
- **LangGraph 사용 (과제 규칙상 금지) — 에이전트는 LangChain의 단발성 도구 호출(`create_tool_calling_agent` + `AgentExecutor`)로만 구현하며, 여러 단계를 오가는 상태 기반 그래프(LangGraph)는 사용하지 않음**
- 실제 MES 시스템과의 실시간 데이터 연동 (지금은 시뮬레이션 데이터 기반)
