# 평가 리포트 — 멀티모달 · 모델 라우팅 · 지연 게이트

마지막 갱신: 2026-09-22

## 결론

1. **보안 정책(ZDR) 때문에 모델을 추론 모델로 바꿨고, 그 대가로 지연이 2배가 됐다.**
   품질은 올랐다(`contract` 0.950~0.975 → 0.975~1.000). **옛 게이트 목표는 두 줄 다 못 지켰다.**
2. **옛 목표는 gpt-4o-mini 시절 숫자였다.** 실측에 맞춰 다시 잡았다 — 텍스트 24초 / 이미지 28초.
3. **모델 라우팅으로 텍스트 요청 비용을 77% 줄일 수 있다.** 다만 최악 케이스 지연이 2배가 되어
   **아직 켜지 않았다.** 원인은 모델 속도가 아니라 재시도 횟수다.
4. **지금까지 "p95"라고 부른 값은 p95가 아니라 "가장 느린 1건"이었다.** 아래 1절 참고.

---

## 1. 먼저 — 지표 이름을 정정한다

`scripts/score_multimodal.py`의 p95 계산은 이렇다.

```python
s[min(len(s) - 1, int(len(s) * 0.95))]
```

케이스가 10건이면 `int(10 * 0.95) = 9` → 정렬한 10개 중 **마지막, 즉 최댓값**이 나온다.
**이 문서의 모든 "최악1건"은 예전 회차 파일에서 `p95` 키로 저장된 그 값이다.** 이름만 바꿨고
계산은 그대로다(기존 회차와 비교하려고 JSON 키는 `p95`로 뒀다).

진짜 p95를 보려면 케이스를 늘려야 한다(20건이면 19번째, 30건이면 28번째).
**n=10에서는 p95를 낼 수 없다** — 이것이 이 리포트의 가장 큰 한계다.

## 2. 측정 환경

| 항목 | 값 |
|---|---|
| 평가셋 | `evals/dataset_multimodal.jsonl` 10건 (정상 2 · 경계 3 · 실패유도 5) |
| 채점 | 규칙 기반 2축 — `visual_extraction`(이미지에서 읽어야 할 것/말하면 안 될 것), `contract`(도메인 규칙 준수) |
| 지연 | `generate_report` 전체 벽시계 시간 (MCP 연결·도구 왕복·재시도 포함) |
| 비용·토큰 | Langfuse 트레이스의 `total_cost` 합 ÷ 케이스 수 |
| 재시도 | `--retries 0` (인프라 재시도 없음). 아래 "재시도 배수"는 **LLM 출력 검증 재시도**를 말한다 |
| 데이터 | CSV 모드 (`data/` 4개) |

**LLM-as-judge는 쓰지 않았다.** 규칙 기반이라 "원인 설명이 말이 되는가" 같은 것은 재지 못한다.

## 4. 점수 노이즈 — 단일값으로 쓰면 안 된다

같은 조건 재측정에서 축이 뒤집힌다. **보고할 때는 반드시 범위로 적는다.**

| 케이스 | 증상 | 관측 |
|---|---|---|
| MM-07 | 사전에 없는 코드 `E-302`를 지어냄 → `visual` 1.000 ↔ 0.900 | gpt-5-mini 4회 중 3회 실패 |
| MM-04 | 계획 정지 `ETC-602`를 원인 목록에 넣음 → `contract` 1.000 ↔ 0.975 | 9/21에 처음 관측 |

⚠️ **"gpt-4o-mini에서는 노이즈가 0이었다"는 정확하지 않다.** 점수 노이즈는 작았지만
**지연 노이즈는 더 컸다** — `noise1`과 `noise2`는 같은 조건인데 최악1건이 13.28초와 29.06초로
2배 넘게 갈렸다. gpt-5-mini 쪽이 지연은 오히려 안정적이다(23.4~25.5).

## 5. 모델 라우팅 — 비용 비교표

이미지가 없는 요청을 더 싼 모델로 보낸다 (`docs/specs/model-routing.md`).
후보는 OpenRouter API에서 단가·지원 파라미터를 직접 읽어 446개 → 1개로 좁혔다
(ZDR 판별 필드가 API에 없어, 실제 요청을 보내 200을 확인하는 방법을 썼다).

### 요청당 비용 (Langfuse 실측)

| 경로 | 설정 | 트레이스 | 재시도 배수 | **요청당 비용** | 절감 |
|---|---|---|---|---|---|
| 텍스트 | gpt-5-mini + `low` **(현행)** | 10 | 1.0x | **$0.003495** | 기준 |
| 텍스트 | gpt-5-nano + `low` | 25 | **2.5x** | $0.001838 | −47.4% |
| 텍스트 | gpt-5-nano + `minimal` | 20 | **2.0x** | **$0.000803** | **−77.0%** |
| 이미지 | gpt-5-mini + `low` **(현행)** | 10 | 1.0x | $0.004236 | 기준 |
| 이미지 | gpt-5-mini + `minimal` | 10 | 1.0x | $0.002854 | −32.6% |

**세 가지를 밝혀 둔다.**

1. **트레이스 평균이 아니라 요청당으로 나눴다.** 재시도가 있으면 트레이스가 케이스보다 많아져,
   트레이스 평균을 쓰면 비용이 2.5배 과소평가된다.
2. **공시 단가를 곱하는 방식은 쓰지 않았다.** 프롬프트 캐싱 때문에 실제 과금과 맞지 않는다
   (Azure 단가로 계산하면 $0.00662인데 실측은 $0.003495였다).
3. **`docs/specs/multimodal.md`에 있던 "gpt-4o-mini 이미지 1장 25,530토큰 / $0.00383" 표는
   무효라 삭제했다(9/21).** ZDR 전환 전 숫자이고, 비교 대상인 두 모델 모두 지금은 쓸 수 없다.

### 입력 토큰이 비용을 지배한다

| 경로 | 평균 입력 토큰 | 평균 출력 토큰 | 입력 비중 |
|---|---|---|---|
| 이미지 있음 (gpt-5-mini) | 17,532 | 1,636 | 91.5% |
| 이미지 없음 (gpt-5-mini) | 15,332 | 1,394 | 91.7% |

`skills/SKILL.md`가 프롬프트에 통째로 들어가기 때문이다.
**이미지 유무의 토큰 차이는 약 14%에 그친다** — 이미지보다 고정 프롬프트가 훨씬 크다.
비용을 더 줄이려면 모델 교체보다 **프롬프트 축소·캐싱이 효과가 크다**(미검증).

## 6. 지연 게이트 재설정

| | 옛 목표 | 근거 | 새 목표 | 근거 |
|---|---|---|---|---|
| 텍스트 | p95 ≤ 10초 | gpt-4o-mini 대조군 9.6~11.1초 | **최악1건 ≤ 24초** | 실측 20.3초 + 여유 |
| 이미지 | p95 ≤ 20초 | gpt-4o-mini 최악 9.2~29.1초 | **최악1건 ≤ 28초** | 실측 23.4~25.8초(6회) + 여유 |

**왜 바꿨나**: 옛 숫자는 gpt-4o-mini 시절에 만든 것이고, 그 모델은 ZDR에서 쓸 수 없다.
추론 모델로 갈아탄 뒤로는 **두 줄 다 한 번도 지키지 못했다.** 목표를 그대로 두면
"항상 실패하는 게이트"가 되어 아무도 보지 않게 된다.

**못 지킨 사실을 분명히 적어 둔다**: 옛 목표(텍스트 10초 / 이미지 20초) 기준으로
9/20 이후 모든 회차가 실패했다. 새 목표는 기준을 낮춘 것이며, 성능이 좋아져서 바꾼 것이 아니다.

**새 목표의 한계**:
- 텍스트 게이트의 근거는 **측정 1회(`gpt5mini` 대조군 20.27초)뿐**이다. 얇다.
- 두 값 모두 "최악 1건"이라 케이스 1건의 운에 좌우된다. 케이스를 30건으로 늘려야 p95가 의미를 갖는다.

## 7. 라우팅을 아직 켜지 않은 이유

| 경로 | 현행 (mini+low) | 라우팅 (nano+minimal) | 판정 |
|---|---|---|---|
| 텍스트 요청당 비용 | $0.003495 | **$0.000803 (−77%)** | 좋아짐 |
| 텍스트 최악1건 | 20.3초 | **41.8초** | **새 게이트 24초 초과** |
| 이미지 경로 | 변화 없음 | 변화 없음 | — |

**gpt-5-nano가 느려서가 아니다.** 개별 LLM 호출은 오히려 훨씬 빠르다.

| 텍스트 경로 | 개별 호출 지연 | 호출 횟수 | 총 시간 |
|---|---|---|---|
| gpt-5-mini + `low` | 10.7 ~ 19.2초 | 10회 | 158.1초 |
| gpt-5-nano + `low` | 7.2 ~ 14.9초 | 25회 | 275.6초 |
| gpt-5-nano + `minimal` | **4.5 ~ 9.1초** | 20회 | **162.2초** |

nano는 호출 하나가 mini의 절반 속도다. 문제는 **1차 응답에서 스키마를 자주 놓쳐 2차 재시도로
회복**한다는 것이고(`degraded: []`이므로 3차 축소 스키마까지는 가지 않는다), 그 재시도가 걸린
**단 한 건**이 "최악1건" 지표를 41.8초로 끌어올린다. 나머지는 4.5~9.1초다.

`effort`를 `minimal`로 낮춰도 재시도는 2.5x → 2.0x로 줄 뿐 사라지지 않았다.
**추론 토큰만의 문제가 아니다.**

> `effort` 허용 값은 문서와 실제 요청으로 확인했다: `minimal` < `low` < `medium` < `high` < `xhigh`.
> **`none`은 400이다** — `Reasoning is mandatory for this endpoint and cannot be disabled.`

## 8. 남은 문제

| # | 문제 | 다음에 할 것 |
|---|---|---|
| 1 | nano의 재시도 2.0x가 미해결 | `response_format`을 `json_object` → **`json_schema`(구조화 출력)**로 올리면 스키마를 강제할 수 있다. gpt-5-nano는 `structured_outputs`를 지원한다(검증 완료). Pydantic 스키마 변환이 필요해 별건이다 |
| 2 | n=10이라 p95를 낼 수 없다 | 평가셋을 30건으로 늘린다 |
| 3 | 텍스트 게이트 근거가 1회뿐 | 대조군을 켠 회차를 2~3회 더 쌓는다 |
| 4 | 텍스트 경로 품질을 채점할 수단이 없다 | `evals/dataset.jsonl` 30건용 채점기가 없다. 대조군은 `contract`를 재지 않는다 |
| 5 | MM-07 · MM-04 노이즈 | 재측정마다 뒤집힌다. 단일값으로 보고하지 말 것 |
| 6 | 측정이 1인 PC에 묶여 있다 | 네트워크·시간대에 따라 지연이 흔들린다. `noise2`의 29.06초가 그 예 |

## 부록 — 재현 방법

```bash
# 현행 설정 그대로 (gpt-5-mini, 라우팅 OFF)
.venv/Scripts/python.exe scripts/score_multimodal.py --tag <회차명> --retries 0

# effort만 낮춰서
MESTORY_LLM_REASONING_EFFORT=minimal .venv/Scripts/python.exe scripts/score_multimodal.py --tag <회차명> --retries 0

# 라우팅 켜고 (.env는 건드리지 않는다 — load_dotenv가 기존 환경변수를 덮어쓰지 않는다)
MESTORY_LLM_MODEL=openai/gpt-5-nano MESTORY_LLM_MODEL_VISION=openai/gpt-5-mini \
  .venv/Scripts/python.exe scripts/score_multimodal.py --tag <회차명> --retries 0
```

비용은 Langfuse에서 세션 `eval-<회차명>` / `eval-<회차명>-noimg`의 `total_cost` 합을
케이스 수(10)로 나눠 구한다. **트레이스 수가 10보다 크면 재시도가 있었다는 뜻이다.**
