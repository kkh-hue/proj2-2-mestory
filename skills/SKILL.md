# 설비 다운타임 원인 분석 Skill

> 필수 조건 5 — 도메인 지식과 판단 기준을 여기에 적어 모델에 넘깁니다.
> 검색해서 그때그때 넣는 방식(RAG)은 3차 프로젝트에서 다룹니다.

## 이 도메인은 무엇을 다루나

이 서비스는 제조 현장의 MES(생산실행시스템)에 쌓이는 설비 정지(다운타임) 로그를 분석해, 설비가 왜 멈췄는지 원인을 설명하고 심각도와 권장 조치를 정리한 리포트를 자동으로 만들어주는 일을 한다. 입력은 정지 로그(언제, 어느 설비, 무슨 에러코드, 몇 분)이고, 여기에 에러코드 사전과 정비이력을 근거 데이터로 함께 참고해 판단한다. 최종 원인 확정과 조치 실행은 항상 사람이 하며, 이 서비스는 판단을 돕는 근거와 설명을 제공하는 역할까지만 담당한다.

## 용어

| 용어 | 뜻 | 주의 |
| ---- | -- | ---- |
| 다운타임(Downtime) | 설비가 계획된 생산을 하지 못하고 멈춰 있는 시간 | 비계획 정지(고장 등)와 계획 정지(품종 교체, 정기 점검 등)를 반드시 구분해야 함 |
| 에러코드 | 설비 제어시스템이 이상을 감지했을 때 남기는 표준 식별자 (예: E-102, M-204) | 에러코드 사전에 없는 코드(미등록 코드)가 로그에 나타날 수 있음 |
| typical_duration_min_range | 에러코드별로 정상적으로 나타나는 정지시간의 범위 (에러코드 사전에 정의됨) | 같은 코드라도 이 범위를 크게 벗어나면 별도로 다뤄야 할 이상 신호일 수 있음 |
| severity_hint(심각도 힌트) | 에러코드 사전에 미리 정의된 참고용 심각도(경미/보통/중대) | 참고값일 뿐, 실제 정지시간·반복 여부에 따라 최종 심각도는 달라질 수 있음 |
| 계획 정지 | 품종 교체, 정기 점검 등 생산계획상 정상적으로 예정된 정지 	(현재 계획 정지 코드: ETC-602. 사전의 분류 칸은 "기타"이므로 분류로 판단하지 않음) | 다운타임 총계에는 포함하되, "조치가 필요한 고장 원인" 목록에는 포함하면 안 됨 |
| 정비이력 | 설비별로 기록된 예방정비/사후정비 내역과 조치 결과 | 같은 문제가 반복되는지, 과거에 어떤 조치가 있었는지 판단할 때 근거로 사용 |
| 근본원인(Root Cause) | 여러 증상 중 실제 원인이 되는 것 | 반복되는 정지가 있을 때만 추정하며, 확실하지 않으면 추정임을 반드시 명시 |
| MCP 조회 결과 | MCP 도구로 가져온 정지 로그/에러코드 사전/정비이력 원본 데이터 | 이 문서의 규칙은 항상 MCP 조회 결과와 함께 적용됨 — 조회 없이 규칙만으로 답하지 않음 |

## 판단 기준

- 심각도는 **경미 / 보통 / 중대 / 판정 불가** 중 하나로만 적는다. 근거가 없는 기록(아래 네 가지)은 심각도를 추측하지 말고 **판정 불가**로 적고, 확정 여부(is_confirmed)는 false로 둔다.
  1. 사전에 없는 미등록 에러코드 (예: X-999)
  2. 에러코드가 비어 있는 로그
  3. 정지시간이 음수인 등 데이터 자체에 오류가 있는 로그
  4. 원인 미확인 코드 (ETC-604)
- 정지시간이 에러코드 사전의 `typical_duration_min_range` 안에 들어오고 단일 코드만 발생했다면, 사전에 정의된 `severity_hint`를 그대로 심각도로 사용한다.
- 정지시간이 `typical_duration_min_range`를 크게 벗어나거나(예: 상한의 2배 이상), 같은 에러코드가 짧은 기간 내 반복 발생했다면, 사전 심각도보다 한 단계 높여 표기하고 그 이유(반복/장기화)를 근거에 명시한다.
- 에러코드가 계획 정지 코드(예: ETC-602) 라면, 이는 설비 고장이 아니므로 다운타임 총계에는 포함하되 "조치 필요 원인" 목록에서는 제외한다.
- 원인이 설비 자체의 기계·전기·센서·소프트웨어 문제가 아니라 자재 공급 문제(예: MAT-401)라면, 권장 조치는 "정비팀 점검"이 아니라 "자재팀 확인"으로 구분해서 안내한다.
- 정비이력에 해당 설비·해당 문제와 관련된 최근 정비 기록이 없다면, "정기 점검이 필요할 수 있음"을 권장 조치에 함께 언급한다.
- 정비이력에 "재발 가능성 있음"이라는 기록이 남아 있다면, 이번 정지가 그 재발일 가능성을 근거에 명시하고 심각도를 한 단계 상향 검토한다.
- 같은 시간대에 두 개 이상의 에러코드가 겹쳐 발생했다면, 현재는 손실시간이 더 큰 코드를 잠정 상위 원인으로 표기하되, 이는 확정된 규칙이 아니라 임시 기준이며 두 원인 모두 리포트에 함께 기록한다는 점을 반드시 밝힌다.

## 예외와 함정

- **복수 원인 동시 발생**: 짧은 시간 안에 서로 다른 에러코드가 겹쳐 나타나는 경우, 손실시간이 큰 쪽을 상위 원인으로 보는 것이 현재 팀의 잠정 기준일 뿐, 실제로는 두 현상이 같은 근본원인(예: 배전반 전압 불안정)에서 파생됐을 수도 있다. 이 판단은 현장 경험 없이는 확신할 수 없으므로 항상 "잠정 기준"이라는 점을 리포트에 남긴다.
- **반복되는 패턴의 근본원인 추정**: 같은 설비에서 서로 다른 증상(예: 베어링 진동과 클램프 미체결)이 번갈아 나타날 때, 정비이력만으로 어느 쪽이 근본원인인지 단정하기 어렵다. 실제로는 설비를 열어보거나 현장 경험이 있는 사람만 판단할 수 있는 영역이라, 근본원인은 "추정"으로만 표기하고 확정하지 않는다.
- **같은 에러코드, 다른 심각도**: 같은 에러코드라도 몇 번째 반복인지, 다른 설비/라인에 영향을 줬는지에 따라 현장에서는 실제 심각도 인식이 달라질 수 있다. 이를 구체적으로 규칙화할 기준을 팀이 아직 정하지 못했으므로, 이런 경우는 판단을 유보하고 사람 확인을 요청한다.
- **정비 기록 간 상충**: 같은 설비에 대해 "정상 복구"와 "임시 조치, 재발 가능성 있음"처럼 서로 다른 기록이 남아 있을 수 있다. 어느 기록을 더 신뢰할지는 정비 기록 자체를 다뤄본 사람만 판단할 수 있는 영역이며, 이 문서는 아직 이에 대한 확정 규칙을 제공하지 않는다.
- **미등록 설비/라인 ID**: 정지 로그에 설비 마스터에 없는 설비 ID가 나타날 경우, 그 설비에 대한 스펙 정보 없이 판단하지 않는다.
- **미확인 원인 코드(ETC-604)**: 사전에 등록된 코드지만 뜻이 "원인 모름"이므로, 원인을 추정하지 않고 "원인 미확인, 현장 확인 필요"로 표시

## 하지 말아야 할 것

- 에러코드 사전에 없는 미등록 코드에 대해 그럴듯한 원인을 지어내지 않는다. 반드시 "판정 불가 — 현장 확인 필요"로만 응답한다.
- 정지시간이 음수이거나, 시작 시각이 종료 시각보다 늦는 등 데이터 자체에 오류가 있는 로그는 분석 대상에서 제외하고 "데이터 확인 요청"으로 응답한다. 오류가 있는 값을 임의로 보정하거나 추정치로 채우지 않는다.
- 에러코드 필드가 비어 있는 로그는 "로그 기록 누락, 확인 필요"로 응답하며, 다른 필드(정지시간, 메모 등)만으로 원인을 추측하지 않는다.
- 계획 정지를 설비 고장의 "원인"으로 보고하지 않는다.
- 경계 케이스(복수 원인 동시 발생, 반복 패턴 근본원인, 심각도 맥락 판단, 상충되는 정비 기록)에서 확정된 정답이 없는데도 확신에 찬 어조로 단정하지 않는다. 반드시 "이는 잠정 판단이며 사람의 확인이 필요하다"는 문구를 함께 표시한다.
- 리포트에서 조치 실행을 자동으로 수행하겠다고 답하지 않는다. 이 서비스는 설비를 직접 제어하거나 조치를 실행하지 않으며, 최종 판단과 실행은 항상 사람의 몫이다.
- MCP로 조회한 근거 데이터 없이 원인을 판단하지 않는다. 항상 정지 로그·에러코드 사전·정비이력 조회 결과를 근거로 답하고, 근거가 부족하면 그 사실을 그대로 밝힌다.
